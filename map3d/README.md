# map3d — 从 PUBG 地图截图重建 3D 模型

把一张 2D 俯视地图截图，还原成带地形起伏和建筑体块的可导入 3D 模型（OBJ）。

```
输入  clipboard-2026-10-23T16-54-04-126Z-eab95c49.png   658 x 481
输出  miramar.obj + miramar.mtl + miramar_tex.png      20 351 顶点 / 40 062 面
```

---

## 一、交付文件

| 文件 | 说明 |
|---|---|
| `miramar.obj` | **主交付物**。地形 + 11 栋建筑，标准 OBJ，2.17 MB |
| `miramar.mtl` | 材质：`earth` 贴地图纹理，`wall` / `roof` 纯色 |
| `miramar_tex.png` | 地形贴图（就是输入截图，地形 UV 与之逐像素对应） |
| `compare.png` | **四联对比图**：输入截图 / 俯视还原 / 斜视 3D / 等轴测 |
| `preview_persp.png` | 斜视透视效果图（看地形起伏） |
| `preview_iso.png` | 等轴测效果图（看建筑分布） |
| `preview_top.png` | 正交俯视渲染（用来和原图逐像素比对） |
| `check_boxes.png` | 检测结果叠加在原图上（核对建筑框和网格标定） |
| `meta.json` | 中间数据：高度场、建筑清单、比例参数 |

**模型规格**

- 场景范围 `609.3 × 445.4 m`
- 地形网格 `166 × 122` 顶点（采样步长 4 px ≈ 3.7 m）
- 地形高度 `-25.3 ~ +35.4 m`
- 建筑 11 栋，高度 `6.0 ~ 15.0 m`，四坡顶

## 二、怎么用

**Blender**

```
File > Import > Wavefront (.obj)
选中 miramar.obj，确认 Path Mode 为 Copy（或保持贴图同目录）
```

导入后地形是 `terrain` 对象（带 UV 和贴图），建筑是 `buildings_wall` / `buildings_roof`。
单位选 Metric，比例 1.0，导入即为真实米制尺寸。

**Unity / UE**

直接拖入工程即可，OBJ + MTL + PNG 三件套放在同一目录，贴图会自动关联。
UE 导入时把 "Combine Meshes" 关掉，可以分别编辑地形与建筑。

**其他**

任何支持 OBJ 的软件（3ds Max、Maya、C4D、Houdini、Rhino…）都能直接读。

## 三、原理

从一张俯视图恢复 3D，本质是三件事：

### 1. 平面位置 —— 由网格标定

地图上有一层淡淡的参考网格。对每列 / 每行求平均灰度，网格线的亮度会明显偏离邻居，
用这个找出了精确位置：

```
竖线  x = 34, 142, 250, 358, 466, 574
横线  y =      108, 216, 324, 432
```

间距全部是 **108 px，零误差**。PUBG 地图一格通常代表 100 m，所以

```
1 px = 100 / 108 = 0.9259 m
```

像素坐标线性映射到世界 XY，这套比例贯穿全流程。

### 2. 高度 —— 用亮度当海拔代理

沙漠地图里「亮 = 砂石高地，暗 = 沟谷 / 植被洼地」，所以灰度可以当高度用。
但不能直接用，要拆成两个尺度：

```
h = (大尺度模糊 σ≈40px − 均值) × 0.55     大尺度 -> 丘陵的总体起伏
  + (中尺度模糊 σ≈10px − 大尺度) × 0.40    中尺度 -> 沟壑、干河床的细节
```

中尺度那一项是关键：干河床（wadi）在灰度上是窄的暗带，只做一次大模糊会被抹平，
只有「中尺度减去大尺度」才能把它作为负值凸显出来，形成真正的凹沟。

### 3. 建筑 —— 亮且暖的规则块

先采样确认了颜色特征，再据此设判据：

| 对象 | RGB 示例 | 亮度 | 饱和度 |
|---|---|---|---|
| 建筑屋顶 | (208, 196, 163) | 208 | **45** |
| 车辆 UI 图标 | (238, 238, 238) | 238 | **0** |
| 沙漠地面 | (70, 65, 54) | 70 | 16 |
| 沟壑底 | (48, 43, 36) | 48 | 12 |

判据 `亮度 > 145 且 18 ≤ 饱和度 ≤ 80`，一次性同时排除：
过暗的地面/沟壑、纯中性灰的 UI 图标。三棱锥测距标记和红圈因为与屋顶同色，
改用「只在已知聚落区域内搜索」+ 面积/边长过滤来排除。

检测出 bbox 后挤出成盒体，顶部做四坡（中心抬脊点），底部向下多延伸 3 m 防止坡地露缝。

---

## 四、两个必须处理的坑

### 坑 1：屋顶会隆起成山

屋顶亮度 200+，如果直接拿灰度算高度，每栋房子下面都会顶起一座小山，
房子再叠上去就变成「悬空楼阁」。

**做法**：先建「建筑 + UI」的 mask，在低分辨率网格上做迭代扩散填补
（每轮把边缘一圈填掉，由外向内渗透，60 轮足够覆盖最宽的 30 px 建筑），
把屋顶从灰度图里抹掉再算高度。

### 坑 2：房子会半陷进坡里

高度场算出来后，房基位置的高度仍然是原始地形的值，房子按 bbox 挤出就会陷进去或悬空。

**做法**：按每个建筑 bbox，取**外围两格一圈**的地形高度中位数作为该建筑的地面高度，
再把 bbox 内的地形统一压到这个高度。房子从此一定坐平。

验证：`meta.json` 里每栋建筑的 `ground_z` 就是压平后的地基高度，
中央房群在 `13.55 ~ 15.55 m` 的台地上，右上聚落在 `1.90 m`，底部村庄一栋在 `-2.20 m`。

## 五、重新生成 / 调参

```bash
# 默认参数，重新生成 OBJ
python build_map3d.py

# 改比例尺（如果那一格不是 100 m）
python build_map3d.py --cell-m 200

# 地形更精细（步长 2px，约 8 万顶点）
python build_map3d.py --step 2

# 换输入图
python build_map3d.py --src D:\other_screenshot.png

# 重新出预览图
python render_preview.py all

# 重新出对比图
python make_compare.py

# 校验 OBJ 合法性
python validate_obj.py
```

`build_map3d.py` 顶部集中了所有可调常量：

```python
CELL_PX        = 108.0    # 网格间距（改这张图的标定就改这里）
ROOF_MIN_LUM   = 145      # 屋顶亮度下界
ROOF_SAT_LO    = 18       # 饱和度下界（排除纯白 UI）
H_LARGE        = 0.55     # 大尺度起伏强度
H_FINE         = 0.40     # 沟壑细节强度
BLD_H_RATIO    = 0.30     # 建筑高 = 宽 × 该比例
BLD_H_MIN/MAX  = 6 / 15   # 建筑高上下限（米）
RIDGE_RATIO    = 0.16     # 四坡顶脊高比例
BUILDING_ROIS  = [...]    # 允许搜索建筑的矩形区域
```

## 六、辅助脚本

| 脚本 | 作用 |
|---|---|
| `tool_calibrate.py` | 网格标定 + 亮度分布统计。108 px 这个数就是它测出来的 |
| `check_boxes.py` | 把检测到的建筑框和网格线画回原图，肉眼核对 |
| `render_preview.py` | 渲染预览（正交俯视 / 透视 / 等轴测），自带软光栅器 |
| `make_compare.py` | 拼四联对比图 |
| `validate_obj.py` | 校验 OBJ：索引越界、退化面、法线朝向、包围盒 |

渲染器是纯 PIL 手写的：画家算法排序 + 朗伯光照 + 2 倍超采样 + 地形裙边 + 建筑投影。
不需要 numpy（本机装不上，走的是纯 Python 路线）。

## 七、已知限制与假设

**假设（无法从单张截图严格证实）**

1. **比例尺**：按 PUBG 地图一格 = 100 m 计算。若实际不同，用 `--cell-m` 改，
   几何形状不变，只是整体缩放。
2. **高度基准**：亮度当海拔是定性近似，不是真实 DEM。沟壑、山脊的位置和走向是对的，
   绝对高程是推出来的。重建后地形高差 60 m，对 Miramar 的缓丘陵属合理量级。
3. **建筑高度**：图上没有高度信息，按「宽度 × 0.30，限制在 6~15 m」推定。
   PUBG 单层房实际约 5~7 m，这里偏大，因为地图比例下建筑像素尺寸偏大。
4. **上/下边界裁切**：右上聚落被图片上边界切断，底部村庄被下边界切断，
   模型只包含可见部分。

**限制**

1. 建筑是**灰盒（greybox）**：bbox 挤出的盒体 + 四坡顶，没有门窗、院墙、附属结构。
2. 相邻建筑若在原图上被院墙连成一片，会被合并成一个体块（中央房群 5 个块有重叠）。
3. 地形只恢复**高度**，没有恢复岩石、植被等材质分层——这些体现在贴图颜色里。
4. 输入必须是**正交俯视图**。斜视、透视、带旋转的截图无法用这套流程（网格检测会失准）。
5. 地形三角面 39 930，建筑 132 面。若导入后嫌重，可在 Blender 里 Decimate，
   或把 `--step` 改大重生成。

## 八、这次做了什么（时间序）

1. 标定网格 → 确认 108 px 间距，定下 1 px = 0.9259 m
2. 采样颜色 → 区分屋顶（饱和 45）与 UI 图标（饱和 0），定下双判据
3. 检测建筑 → 限定 4 个聚落 ROI，得到 11 个 bbox，叠回原图核对无误
4. 剔除屋顶 → 迭代扩散填补 1007 个格子，再算高度场
5. 压平地基 → 每栋按外围地面中位数压平
6. 导出 OBJ → 地形 39 930 面 + 墙面 88 + 屋顶 44
7. 写软光栅器 → 俯视验证位置、斜视看效果，逐步修掉「悬浮布」「黑块阴影」「马赛克」「裙边被剔除」
8. 校验 → 索引 0 越界、退化面 0、地形 39 920 面朝上 0 翻面
